# VESPER Repo Audit — Ground Truth (2026-07-26)

**Method:** static inspection only. Nothing was fixed or modified. Evidence is file
paths, `pip freeze` of the active `.venv`, and the retained runtime logs
(`logs/vesper.log`, `.log.1`, `.log.2`, `jarvis.log`).

**The one-line resolution of the contradiction:** Almost every claimed component
*exists as committed code*. But `python main.py` boots the **legacy v1 stack**
(tkinter `ui/hud_overlay.py` + `agents/voice_agent.py`), **not** the v2 stack. The
v2 gateway/HUD/voice are real code behind a *separate* entrypoint
(`python -m gateway.server`) that `main.py` never launches, their runtime deps are
**not installed** in the active venv, and the active venv is **Python 3.9.6** (v2
voice was built under 3.11). So the runtime log showing legacy VoiceAgent hammering
the mic is exactly what the default entrypoint produces — the log doesn't contradict
the commits, it reveals that v2 was added *alongside* v1 rather than replacing the
boot path.

## Plain-English Summary

**Actually complete (as coherent, committed, runnable-under-3.9 code): P00 through P10
— the entire v1 stack.** Planner as the sole input path, tool registry + guardian
tiers, sensors, proactive engine with cooldowns, LangSmith tracing with local
fallback, Gmail/apple_pim/Notion MCP servers, rich CLI, day-planning, and TESTPLAN all
exist and cohere. The v1 stack is what runs today.

**Written but not actually wired up / not runnable in the active environment: PV0–PV4
(the v2 stack).** The code is genuinely there — a real FastAPI gateway, a real Tauri
project, and real openWakeWord/VAD/faster-whisper/Kokoro voice modules — and every
PV/PC commit exists. But:

- **The default entrypoint (`python main.py`) still boots the legacy stack**: tkinter
  `ui/hud_overlay.py` and the old `agents/voice_agent.py`. It never starts the gateway
  (that's a separate `python -m gateway.server` process), never launches the Tauri
  HUD, and never uses the new voice modules. The v2 pieces are additive clients of a
  gateway the main process doesn't run.
- **The active venv can't run v2 anyway**: it's Python 3.9.6, and `sounddevice`,
  `openwakeword`, `faster-whisper`, `kokoro-onnx`, `webrtcvad`/`silero-vad` are all
  uninstalled (the v2 voice code was compiled under 3.11 per `__pycache__`).
- **No custom wake-word model was ever committed** (`voice/models/` is empty) despite
  PV3's claim.

**Not built at all:** the custom `.onnx` wake model (V2d).

**On the specific defects:** D2 (3 s mic retry, no backoff/give-up), D3 (synchronous
TTS blocking the bus 3+ s), D5 (`AgentStartedEvent` fired before its only HUD
subscriber attaches), D6 (`openai/gpt-oss-120b` + focus/calendar off), and D7
(MacOSControl/WebSearch/Plugin agents boot but their `IntentRecognizedEvent` handlers
are orphaned) are **all confirmed in code**. **D1 is a misread** — EventBus is a
genuine singleton; it's one instance with two identically-worded log lines, not two
instances. **D4 could not be confirmed** — the "macOS 26 / 1601" string exists in no
file and no log, and the legacy HUD is tkinter, not pyobjc, so nothing in this repo
would raise it.

Net: the previous sessions' "complete" is true at the **file-and-commit** level and
false at the **"this is what runs"** level. v1 is the working product; v2 is
code-complete-on-paper but dark — not on the boot path and not installable in the
current 3.9.6 environment.
